# 测试方案

测试以需求 R1–R6 为依据，先固定输入、决策及调用顺序，再开发实现。使用标准库 unittest，测试数据来自随项目交付的 JSON 样例。逻辑时间和故障注入用于复验异常分支。

| 用例 | 需求 | 输入与验证点 | 通过条件 |
| --- | --- | --- | --- |
| T01 | R3 | 授信原文样例 | PASS，额度 30000，期数 12，LOW，模型分 0.82，无原因码 |
| T02 | R3 | 下单原文样例 | ALLOW，额度 4999，免验证，LOW，欺诈概率 0.08 |
| T03 | R3 | 定价原文样例 | PRICE_OK，利率 0.15，APR 0.162，LOW，LOW_RISK_PREMIUM |
| T04 | R3、R4 | 高风险客户授信与下单 | 授信硬拒并保留全部命中，下单硬拒，跳过模型 |
| T05 | R2、R3 | 模型阈值临界值及配置变更 | 授信分等于阈值时通过，阈值提高后转人工。下单概率等于阈值时要求验证 |
| T06 | R2、R3 | 金额等于额度、金额超出额度、七日金额临界值 | 等于上限允许，超出触发相应规则。请求中额度无法覆盖快照额度 |
| T07 | R3 | 基准利率触发上下限、高风险定价、有效竞品价匹配 | 利率截断到 0.08 或 0.24，APR 同步计算。高风险溢价及原因码可区分，低风险可匹配满足差额与定价区间的竞品价 |
| T08 | R1、R4 | 非对象、未知场景、必填缺失、金额别名冲突、非法数字及日期 | INVALID、PARAM_INVALID，入口审计有 trace_id，无下游调用 |
| T09 | R1、R5 | 正常链路，注入调用记录 | 同一 trace_id、事件顺序正确，批取一次，模型只收到配置子集及对应元数据，逻辑耗时正确 |
| T10 | R4、R5 | 模型所需特征首次缺失 | 只补取所缺特征一次，模型调用两次，最终恢复，保存恢复原因及快照 |
| T11 | R4 | 模型所需特征持续缺失 | 只补取一次，转人工，无批准金额 |
| T12 | R4、R5 | 可默认特征缺失和过期、规则关键特征过期 | 默认值保留缺失根因与来源，允许完成预测。关键依赖过期时降级 |
| T13 | R4、R5 | 特征超时，预算在回补时耗尽 | 可观察到超时状态，预算无超支，降级原因匹配 |
| T14 | R4 | 模型超时覆盖三场景 | 授信及定价 REVIEW，下单 CHALLENGE，保留原因码和耗时 |
| T15 | R4、R5 | 特征版本不匹配且跳过规则、模型直接输入错误类型或子项版本不符 | 模型结果不可用于决策，适用的失败状态和原因码可检验 |
| T16 | R2 | 损坏的配置引用与不支持的规则操作 | 启动时明确拒绝配置 |
| T17 | R5、R6 | 三个 CLI 样例、非法 JSON、故障参数、stdin 和 --audit | stdout 可解析为 JSON，stderr 为有序审计事件，退出码符合契约 |
| T18 | R1、R5 | 同一实例并发运行正常与故障请求 | 各请求的预算、特征和调用记录彼此隔离 |
| T19 | R4、R5 | 未知实体、省略竞品利率的样例 | 未知客户没有模拟批准，独立的请求来源正确归一 |
| T20 | R6 | 解压实际交付包后复跑 | ZIP 完整，所有自动化测试通过，README 命令可运行 |

## 执行与退出条件

在项目根目录运行 `python3 -m unittest discover -s tests -v`。T01–T19 随项目自动化执行。T20 对最终交付包执行并记录。每次修复后重新运行全套测试。只有全部用例通过，且实际样例输出与契约一致时交付。测试覆盖模拟链路、配置、命令行与数据契约。
